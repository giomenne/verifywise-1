# Render Deployment Guide

This guide will help you deploy VerifyWise to Render.

## Prerequisites

1. A [Render account](https://render.com)
2. Your repository pushed to GitHub, GitLab, or Bitbucket
3. Environment variables documented below

## Quick Start

### Option 1: Using Blueprint (Recommended)

1. **Fork/Push your repository** to GitHub, GitLab, or Bitbucket

2. **Log into Render Dashboard** and click "New +" → "Blueprint"

3. **Connect your repository** and select the branch (e.g., `develop` or `main`)

4. **Render will automatically detect** the `render.yaml` file and create all services

5. **Configure environment variables** (see below)

6. **Deploy** - Render will build and deploy all services automatically

### Option 2: Manual Service Creation

If you prefer to create services manually:

1. Create a **PostgreSQL** database
2. Create a **Redis** instance
3. Create **Web Services** for:
   - Backend API
   - Bias & Fairness Backend
   - Frontend (Static Site)
4. Create a **Worker** service for background jobs

## Environment Variables

### Required Variables

#### Backend Service (`verifywise-backend`)

```env
# Database (auto-configured from PostgreSQL service)
DB_HOST=<auto-set>
DB_USER=<auto-set>
DB_PASSWORD=<auto-set>
DB_PORT=<auto-set>
DB_NAME=<auto-set>
DB_SSL=true
REJECT_UNAUTHORIZED=false

# Redis (auto-configured from Redis service)
REDIS_URL=<auto-set>

# JWT (auto-generated)
JWT_SECRET=<auto-generated>

# API Configuration
ALLOWED_ORIGINS=https://verifywise-frontend.onrender.com
# Or comma-separated: https://yourdomain.com,https://www.yourdomain.com

# Bias & Fairness Service URL (set after deployment)
FAIRNESS_AND_BIAS_URL=https://verifywise-bias-fairness.onrender.com

# Email Configuration (choose one)

# Option 1: Resend
EMAIL_PROVIDER=resend
RESEND_API_KEY=re_your_api_key_here
EMAIL_ID=noreply@yourdomain.com

# Option 2: SMTP
# EMAIL_PROVIDER=smtp
# SMTP_HOST=smtp.gmail.com
# SMTP_PORT=587
# SMTP_USER=your-email@gmail.com
# SMTP_PASS=your-app-password
# SMTP_SECURE=true
# EMAIL_ID=noreply@yourdomain.com

# Misc
MOCK_DATA_ON=false
NODE_ENV=production
PORT=10000
HOST=0.0.0.0
```

#### Frontend Service (`verifywise-frontend`)

```env
# Backend API URL (set after backend is deployed)
VITE_APP_API_BASE_URL=https://verifywise-backend.onrender.com

# App Configuration
VITE_IS_DEMO_APP=false
VITE_IS_MULTI_TENANT=true

# Slack Integration (optional)
VITE_SLACK_CLIENT_ID=your_slack_client_id
VITE_SLACK_URL=https://slack.com/oauth/v2/authorize
VITE_IS_SLACK_VISIBLE=true
```

#### Bias & Fairness Service (`verifywise-bias-fairness`)

```env
# Database (auto-configured)
DB_HOST=<auto-set>
DB_USER=<auto-set>
DB_PASSWORD=<auto-set>
DB_PORT=<auto-set>
DB_NAME=<auto-set>

# Backend URL (set after backend deployment)
BACKEND_URL=https://verifywise-backend.onrender.com

PORT=10000
```

#### Worker Service (`verifywise-worker`)

Same as backend, but only needs:
- Database connection
- Redis connection
- JWT_SECRET (sync from backend)

## Deployment Steps

### 1. Initial Setup

1. Push your code to GitHub/GitLab/Bitbucket
2. In Render Dashboard, create a new Blueprint
3. Connect your repository
4. Render will read `render.yaml` and create all services

### 2. Configure Environment Variables

After services are created:

1. **Set `ALLOWED_ORIGINS`** in backend service:
   ```
   https://verifywise-frontend.onrender.com
   ```
   Or your custom domain if you've set one up.

2. **Set `VITE_APP_API_BASE_URL`** in frontend service:
   ```
   https://verifywise-backend.onrender.com
   ```

3. **Set `BACKEND_URL`** in bias-fairness service:
   ```
   https://verifywise-backend.onrender.com
   ```

4. **Set `FAIRNESS_AND_BIAS_URL`** in backend service:
   ```
   https://verifywise-bias-fairness.onrender.com
   ```

5. **Configure email service** (choose Resend or SMTP - see above)

### 3. Run Database Migrations

The backend service runs migrations automatically on startup via:
```bash
npm run migrate-db && node dist/index.js
```

If migrations fail, you can run them manually:
1. SSH into the backend service (if available)
2. Or use Render's shell: `cd Servers && npx sequelize db:migrate`

### 4. Verify Deployment

1. Check backend health: `https://verifywise-backend.onrender.com/api/docs`
2. Check frontend: `https://verifywise-frontend.onrender.com`
3. Check bias-fairness: `https://verifywise-bias-fairness.onrender.com/`

## Custom Domains

1. Go to your service settings in Render
2. Click "Custom Domains"
3. Add your domain
4. Update DNS records as instructed by Render
5. Update `ALLOWED_ORIGINS` to include your custom domain

## Scaling & Performance

### Upgrade Plans
- Change plan in `render.yaml` or in service settings
- Recommended for production: `standard` or higher

### Scaling Workers
- Multiple worker instances: Create additional worker services
- Or increase plan to allow more concurrent workers

### Monitoring
- Render provides built-in metrics and logs
- Check service logs in Render Dashboard
- Monitor database connections and Redis usage

## Troubleshooting

### Backend Won't Start
- Check database connection (verify DB credentials)
- Check Redis connection
- Review logs in Render Dashboard
- Ensure migrations ran successfully

### Frontend Shows API Errors
- Verify `VITE_APP_API_BASE_URL` is set correctly
- Check CORS settings in backend (`ALLOWED_ORIGINS`)
- Verify backend is running and healthy

### Worker Not Processing Jobs
- Check Redis connection
- Verify worker service is running
- Check logs for job errors

### Database Connection Issues
- Verify `DB_SSL=true` for Render's PostgreSQL
- Check `REJECT_UNAUTHORIZED=false` if using self-signed certs
- Ensure database is in same region as services

## Cost Optimization

- Start with `starter` plans for all services
- Monitor usage in Render Dashboard
- Upgrade only services that need more resources
- Consider using Render's free tier for development/testing

## Security Notes

1. **Never commit** `.env` files or secrets
2. Use Render's **environment variables** for all secrets
3. Rotate `JWT_SECRET` periodically
4. Use **HTTPS only** (Render provides this automatically)
5. Keep database backups enabled in Render
6. Review `ALLOWED_ORIGINS` regularly
